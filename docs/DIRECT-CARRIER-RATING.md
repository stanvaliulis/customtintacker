## Local runtime integration

`quote-service.ts` parses a strict client request (product ID, quantity, standard-024 backing and full destination); it rejects client prices, dimensions, owner IDs and unknown fields. Owner resolution uses the existing authenticated/guest production context with createOwner=false, only after configuration is enabled. `catalog-binding.ts` resolves server product data and rejects changed dimensions, unsupported material/backing, unavailable products and quantities below MOQ. Only four standard-aluminum profiles are supported; unknown variants require review.

Each server-generated random quote ID resolves to an owner-bound record, with hashes covering the complete address, cart, current catalog, packing, services, origin, ship date and configuration revision. Retrieval revalidates those inputs and expiry, never reuses caller amounts. Memory storage is bounded/ephemeral for local operation; restart or eviction requires a new estimate. `quote-postgres.ts` and `shipping-quote-schema.sql` are prepared for reviewed persistent storage; no SQL was executed and no permission grants are included. Stored records contain rates and hashes, not raw destination addresses. Runtime persistence connection/schema/retention setup needs explicit approval before enablement.

The UI requires address type, invalidates results on cart/address/backing changes, ignores late responses, removes expired rates, labels guessed packing and keeps estimates outside the order total. Missing pickup/configuration, invalid requests or failed providers cannot become free shipping. The legacy USPS fixture endpoint remains expired and the cart no longer calls it. No shipping estimate is accepted as payment authority.
